## 写在前面：Git 是什么

Git 是当前最先进、最主流的**分布式开源版本控制系统**，核心能力就是版本控制。具体而言，是面向代码文件的版本控制：代码的任何修改历史都会被记录管理起来，意味着可以恢复到以前的任意时刻状态。Git 支持跨区域多人协作编辑，是团队项目开发的必备基础，也是程序员的必备技能。

主要特点：

- 开源免费，使用广泛
- 强大的代码历史版本管理，直接记录完整快照（完整内容而非差异），支持回滚、对比
- 分布式多人协作的代码协同开发，几乎所有操作都是本地执行的，支持代码合并、代码同步
- 简单易用的分支管理，支持高效地创建分支、合并分支

以上特点对于比赛而言具有重要意义：

- **代码复用**：虽然各兵种区别较大，但部分功能代码具有极强的复用性（如电机通信、PID 控制器、裁判系统数据读取等）。负责编写通用代码的人员可将可用代码上传到远程仓库，使用者根据需要拉取或同步代码；发现问题后也可把修复的版本同步回远程仓库，避免代码从零构建的诸多问题，也无需完全下载新代码，只需同步修改部分。
- **代码回滚**：修改代码过程中往往会出现问题，导致原先可用的版本失效。此时可通过 Git 对比修改部分或直接版本回退，保证赛场上具有相对稳定的表现；也避免了保存诸多不同版本代码压缩包的麻烦。

> 本教程目的在于让你**快速掌握在 VS Code 中使用 Git**，而非 Git 的详细教程。

## 所需插件

1. **VS Code 自带的「源代码管理」**：若左侧菜单栏未显示，右键左侧菜单栏勾选「源代码管理」调出。
2. **Git History 与 Git Graph 扩展**：在 VS Code 扩展中搜索安装。

## 1. 提交代码修改并上传至远程仓库

### 初始化仓库

用 VS Code 打开项目后，选择「源代码管理」，点击「初始化仓库」；也可以使用命令行：

```bash
git init
```

### 暂存更改

为查看及添加修改的便利，可点击「源代码管理」栏右侧的「以树形式查看」按钮，把代码修改显示为各文件夹下的修改。

- 点击「更改」栏目中文件夹或文件右侧的「**暂存更改**」按钮，把修改添加到「暂存的更改」栏目。
- 误添加的可点击「暂存的更改」栏目中的「**取消暂存更改**」按钮取消。

文件右侧的字母表示状态：**U** 未跟踪、**M** 已修改、**A** 新增、**D** 已删除。

### .gitignore

对于某些始终不进行跟踪（即不储存文件修改）的文件，可在工程目录下新建 `.gitignore` 文件，在其中添加不进行跟踪的文件与文件夹名称（文件夹需以 `/` 结尾）。此后源代码管理中便不再显示相关文件。

### 提交

确认更改暂存完成后，在「源代码管理」栏目下方的文本框中输入有关本次提交的**描述性文本**（方便以后快速了解本次修改的大体内容），点击下方「提交」按钮提交到仓库。

::: tip 建议
本次提交涉及的修改内容应有具体范围，且与提交描述相对应，不要一次性提交多种不同内容的修改，以避免混淆。
:::

### 发布到远程仓库

对于新建的仓库，完成首次提交后可点击「源代码管理」栏目中的「**发布 Branch**」按钮，把当前仓库发布到远程仓库。随后填写远程仓库名称（默认为工程文件夹名称），并选择仓库类型：

- **private**：只允许团队中的人查看
- **public**：允许所有人查看

> 战队的代码全部使用 **private**。

这样创建的远程仓库位于 GitHub 上个人对应用户的仓库中。若计划把代码推送到指定远程仓库，可在新建远程仓库后，点击「源代码管理存储库」栏目中的「远程」→「添加远程存储库」，输入远程 URL 与仓库名称后回车，即可实现与远程仓库的关联；再点击「发布分支」按钮把本地仓库发布至远程仓库。

## 2. 代码修改历史查看与对比

提交多次后，点击「源代码管理存储库」栏目中的「**Git: View History (git log)**」按钮，即可查看所有历史提交。

- 点击某次提交，再点击某文件右侧的「**Previous**」按钮，可查看相比上一次提交做出的改变（左侧为修改前，右侧为修改后）。
- 查看经过多次提交后的对比：先点击作为对比中「修改前」的提交右侧的「More」→「Select this commit ...」，再点击作为「修改后」的提交右侧的「More」→「Compare with ...」。
- 此时左侧资源管理器栏多出「**COMPARE COMMITS**」栏目，显示两次提交发生改变的所有文件，点击想查看的文件即可观看对比。

## 3. 修改撤销与代码回滚

### 撤销当前修改

- 修改还位于「更改」栏目时，点击文件右侧的「**放弃更改**」按钮可撤销整个文件的修改。
- 只想撤销某文件中的部分修改时，点击「更改」栏目下的对应文件，在右侧工作树中点击对应部分的「**还原块**」按钮，即可撤销部分修改。

### 回滚到某次提交

以上方法只限于撤销到上一次提交。若想撤销到某次提交，点击「源代码管理存储库」栏目的「Git History (git log)」，点击计划回退到的提交右侧的 **Soft** 或 **Hard** 按钮：

- **Soft**：把代码回滚到对应提交时的状态，但所有修改情况保留在「暂存的更改」中（代码仍处于未回退状态），此时可「取消暂存更改」进一步撤销部分甚至全部修改，实现全部或部分回滚。
- **Hard**：强制把代码恢复到所选提交，并把所选提交后续进行的提交全部放弃，Git History 刷新后不再显示后续提交。

### 回滚后的恢复

回滚后若想把代码变到被回退提交之后的某次提交，可在终端输入：

```bash
git reflog
git reset --hard 版本号
```

`git reflog` 会显示所有做出的操作，然后通过命令行把代码变到某次版本号。

> 若终端因中文产生乱码，可通过以下命令把默认编码改为 UTF-8：
> ```bash
> chcp 65001
> ```

## 4. 分支创建、切换与合并

### 创建分支

点击「源代码管理存储库」栏中对应的「创建分支」按钮，输入分支名称即可创建。

### 切换分支

点击「源代码管理存储库」栏中当前分支名称，根据提示切换到想要的分支。

### 合并分支

先把分支切换到目标分支（如 `main`），再选择「分支合并」，根据提示选择要合并的分支（如 `git-dev`）；若合并部分没有冲突，则自动合并完成。

### 冲突解决

当两个分支的提交存在冲突时，合并后需要手动解决冲突。解决冲突后点击右下角「完成合并」，输入合并信息，点击继续即可完成分支合并。

## Git 提交规范

使用以下格式提交 commit，不限制中英文：

```
<type>(<scope>): <subject>
```

| type | 说明 |
| --- | --- |
| feat | 新增 / 修改功能 (feature) |
| fix | 修补 bug (bug fix) |
| docs | 文档 (documentation) |
| style | 格式（不影响代码运行的变动，如空白、格式化、缺少分号等） |
| refactor | 重构（既不是新增功能，也不是修补 bug 的代码变动） |
| perf | 改善效能 |
| test | 增加测试 |
| chore | 构建程序或辅助工具的变动 (maintain) |
| revert | 撤销回退先前的 commit |

- **必要字段**：`type` 代表 commit 的类别
- **可选字段**：`scope` 代表 commit 影响的范围，如 `Middlewares`、`Devices` 等
- **必要字段**：`subject` 代表 commit 的简短描述，50 字以内，结尾不要加句号
