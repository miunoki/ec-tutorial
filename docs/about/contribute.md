# 贡献指南

本教程是队内共享的知识库，**人人可编辑**。你的每一处补充，都在帮下一届新同学少走弯路。

## 你可以贡献什么

- **补全正文**：把标记「🟡 待填充」的页面按大纲写完
- **新增页面**：教程里还没有、但你认为值得记录的知识点
- **修正错误**：发现笔误、过时内容、错误说法，直接改
- **补充资料**：好的参考链接、队内文档、调试经验

## 动手前的约定

1. **先看状态**：页面顶部 `::: tip 状态` 标注了是否已有人负责，避免重复劳动
2. **按大纲写**：优先补全「建议大纲」里的章节，保持结构一致
3. **注明来源**：引用外部资料时附上链接，涉及队内文档注明版本
4. **避免敏感信息**：不要上传未公开的机械图纸、代码核心等
5. **注明作者与日期**：方便后续同学找到原作者请教

## 四步完成一次贡献

1. **Fork / Clone 仓库**，新建分支（如 `feature/pid-tuning`）
2. **编辑或新增 `.md` 文件**（Markdown 语法见仓库根目录的 `CONTRIBUTING.md`）
3. **本地预览**：`npm install` 后运行 `npm run docs:dev` 确认排版正常
4. **提交 Pull Request**，等负责人 Review 合并

## 写作风格建议

- 面向零基础，多用「是什么 → 为什么 → 怎么做」的结构
- 配图优先：接线图、波形图、实物照片比文字更直观
- 每个知识点配一个可运行的实验或代码片段
- 少用行话，首次出现的术语给一句解释
